# HexQuest Economy — Модернизация Геймплея: Brainstorm & Детальный План Реализации

Этот документ содержит комплексный анализ вашей идеи и пошаговый технический план модернизации игры **HexQuest Economy**. Мы превращаем цикличную и изолированную сборку фигур в глубокую стратегическую петлю взаимодействия между строительством собственной базы, поиском чертежей («мини-монументы») на процедурных уровнях и защитой ядра от волн наступающих ботов.

---

## 1. АНАЛИЗ ИДЕИ И ГЕЙМПЛЕЙНАЯ ПЕТЛЯ (THE CORE LOOP)

### Текущая проблема игрового цикла
Ранее цикл выглядел так: 
1. Игрок заходит в StoryBuild, собирает фигуры из блоков.
2. Когда блоки/фигуры кончаются, он идет играть в стандартные уровни, чтобы выбивать плиты разной высоты.
3. Получив плиты, он возвращается в StoryBuild и... снова просто собирает фигуры. 

**Чего не хватает:** Глобального вызова (Endgame Challenge). Фигуры собираются ради самих фигур, а ландшафт базы не подвергается угрозам. Нет мотивации строить умную, защищенную архитектуру.

### Новая концепция: «Оборона Ядра и Поиск Чертежей»

```
+-----------------------------------------------------------------+
|                                                                 |
|                      1. РЕЖИМ СТРОИТЕЛЬСТВА БАЗЫ                 |
|       - Игрок строит стены, возвышенности и турели вокруг Ядра   |
|       - Расходный материал — плиты и гексы, добытые в кампаниях  |
|                                                                 |
+-------------------------------+---------------------------------+
                                |
                   Экспорт базы | Испытание на прочность
                                v
+-----------------------------------------------------------------+
|                                                                 |
|                        2. РЕЖИМ ОСАДЫ БАЗЫ                      |
|       - База переносится в активный уровень                     |
|       - Волны ботов идут на ядро, используя Staircase Rule      |
|       - Цель: Выстоять таймер или уничтожить всех ботов         |
|                                                                 |
+-------------------------------+---------------------------------+
                                |
             Нужны новые плиты  | Схемы для фигурных турелей
                 и материалы    |
                                v
+-----------------------------------------------------------------+
|                                                                 |
|                   3. ИССЛЕДОВАТЕЛЬСКИЕ УРОВНИ                   |
|       - Поиск и активация 3 мини-монументов на карте            |
|       - Раскрытие схемы секретной фигуры (чертежа)              |
|       - Сбор фигуры в условиях помех от коварных ботов          |
|                                                                 |
+-----------------------------------------------------------------+
```

#### А. Режим Строительства Базы (Преобразование StoryBuild)
* **Ядро Энергии (Core):** В центре базы устанавливается неуязвимый в режиме строительства объект — Энергетическое Ядро.
* **Свобода планирования:** Игрок расставляет добытые в приключениях плиты разной высоты ($L0$ - $L9+$), формируя лабиринты и искусственные препятствия.
* **Строительные правила:** Здесь полностью работают геологические правила (Staircase Rule, Gradient Lock и Требование Поддержки Соседей для высоких плит). Высота плит имеет решающее значение: боты не могут запрыгнуть на высоту $> 1$ уровня без ступеней!

#### Б. Исследовательские Уровни и Сбор Фигур
* **Мини-Монументы:** Чтобы узнать, какую фигуру (чертеж оборонительной турели или супер-гекса) нужно собрать в уровне, игрок должен исследовать туман войны и активировать **3 Мини-Монумента** (требуется подойти вплотную и потратить ход).
* **Раскрытие Схемы:** Как только активирован 3-й монумент, поверх сетки проецируется полупрозрачный голографический контур целевой фигуры.
* **Усложняющий фактор (Боты-Диверсанты):** Пока игрок пытается выложить фигуру из материалов, боты спавнятся по краям карты и идут ломать уложенные плиты (используют DIG для раскопки и понижения уровней плит игрока). Игроку приходится оборонять строящуюся фигуру.
* Сбор фигуры на уровне материализует её в рюкзак игрока как готовую оборонительную турель для базы.

#### В. Испытание Базы (Режим Осады / Tower Defense)
* Спроектированная игроком база переносится в боевой режим.
* По краям карты спавнятся штурмовые боты во главе с ботом-разрушителем (`DESTROYER`).
* **Логика поиска пути (Pathfinding):** Боты рассчитывают кратчайший путь до Ядра, учитывая высоту гексов. Если они встречают непреодолимую стену (перепад высоты $\ge 2$), они пытаются обойти её. Если прохода нет, боты со статусом `SABOTEUR` начинают бурить проход (разрушать плиты игрока).
* **Задача игрока:** Выдержать осаду в течение 3-5 минут (или $N$ ходов), активно используя добытые турели, активируя ловушки на плитах и сдерживая волны врагов.

## 2. ПОШАГОВЫЙ ПЛАН РЕАЛИЗАЦИИ ПО ФАЙЛАМ

Ниже представлен детальный план изменений, структурированный по задействованным модулям кодовой базы.

### ЭТАП 1: Расширение Модели Данных (`/types.ts`)

Необходимо добавить новые типы и расширить существующие структуры для работы с ядрами, монументами и состоянием защиты.

1. **В структуру `HexCell` (или `HexMetadata`):**
   ```typescript
   export enum SpecialStructureType {
     NONE = 'NONE',
     MONUMENT = 'MONUMENT',
     MINI_MONUMENT = 'MINI_MONUMENT',
     CORE = 'CORE',
     TURRET = 'TURRET'
   }
   // Расширяем метаданные ячейки
   isMiniMonument?: boolean;
   isCore?: boolean;
   isActivated?: boolean;
   durability?: number; // для разрушаемых стен/плит базы
   ```
2. **В структуру состояния игры `GameState` / `LevelState`:**
   ```typescript
   export interface DefenseState {
     isDefenseMode: boolean; // запущен ли режим осады базы
     coreHealth: number;     // здоровье ядра (например, 100)
     maxCoreHealth: number;
     survivalTimer: number;   // оставшееся время в секундах (или ходах)
     currentWave: number;
     spawnPoints: { q: number; r: number }[];
   }

   export interface PuzzleState {
     miniMonumentsActive: number; // сколько активировано (0 из 3)
     isSchemeRevealed: boolean;   // раскрыта ли схема фигуры
     targetShapeId?: string;      // ID собираемой фигуры
   }
   ```

---

### ЭТАП 2: Модернизация Строителя Базы (`/components/StoryBuilderView.tsx` и `StoryBuilderData.ts`)

Превращаем песочницу StoryBuilder в полноценный Конструктор Форпоста.

1. **Размещение Ядра:**
   * В центре карты (`q: 0, r: 0`) фиксируем ячейку с флагом `isCore: true` и визуализируем ее как анимированное энергетическое ядро (используя неоновое свечение в Pixi.js или специальную 3D/2D иконку). Она неуязвима для удаления.
2. **Инвентарь стройматериалов:**
   * Ограничиваем постройку высокоуровневых плит. Игрок может использовать только те плиты-блоки, которые реально заработал/эвакуировал из уровней кампании (синхронизация со `store.ts`).
3. **Кнопка «Испытать оборону базы» (Launch Siege):**
   * При нажатии запускается триггер перехода в режим Осады. Текущий ландшафт копируется в игровой движок (`GameEngine`), состояние переключается в `isDefenseMode = true`.

---

### ЭТАП 3: Логика Уровней-Головоломок с Монументами (`/campaign/levels.ts`)

Создаем шаблоны и конфигурируем новые уровни с поиском чертежей.

1. **Генерация Уровня:**
   * На карте спавнятся 3 мини-монумента на удалении не менее 3-4 гексов друг от друга. Территория покрывается туманом войны (Fog of War).
2. **Обработка Активации:**
   * Когда фигура игрока наступает на соседний с `MINI_MONUMENT` гекс и нажимает кнопку взаимодействия:
     * Монумент меняет текстуру на активную (свечение).
     * `miniMonumentsActive` увеличивается на 1.
3. **Голографический Гайд:**
   * При достижении `miniMonumentsActive === 3` на карте проецируется контур фигуры (например, подкрашиваются целевые гексы сетки полупрозрачным цветом).
   * Игрок должен выстроить плиты нужной высоты на этих гексах.

---

### ЭТАП 4: Поведение Вражеского ИИ в режиме Обороны (`/engine/systems/AiSystem.ts` и `MovementSystem.ts`)

Определяем интеллектуальные алгоритмы для штурмующих ботов.

1. **Алгоритм поиска Ядра (Pathfinding to Core):**
   * Модифицируем расчет весов ребер в графе движения ботов.
   * `targetHex` для всех ботов выставляется в координату Ядра `(0, 0)`.
   * Бот строит оптимальный путь с учетом правила ступеней (высота $\le 1$). 
2. **Саботаж и Разрушение (SABOTEUR / DESTROYER):**
   * Если бот заблокирован высокими плитами игрока и нет обходного пути:
     * Бот переходит в осадный режим. Он начинает бурить гекс перед собой (используя `DIG`), постепенно уменьшая стойкость плиты игрока до $L0$ или превращая её в `VOID`.
   * Игрок теряет оборонительный рубеж, если вовремя не остановит саботажника.
3. **Атака Ядра:**
   * Когда бот оказывается на смежной ячейке с Ядром (Core), он наносит периодический урон `coreHealth -= damage`.

---

### ЭТАП 5: Система Победы и Проигрыша (`/engine/systems/VictorySystem.ts`)

Прописываем новые триггеры завершения игровых сессий.

1. **Убеждение Обороны (Siege Victory / Defeat):**
   * **Поражение:** Если `coreHealth <= 0`. Ядро взрывается, база разрушена, ресурсы на постройку плит сгорают.
   * **Победа:** Если `survivalTimer <= 0` (игрок продержался отведенное время) или уничтожены все штурмовые боты. Игрок получает ценные награды, умножение опыта и уникальные рецепты турелей.
2. **Убеждение Сбора Фигуры (Puzzle Level):**
   * Победа засчитывается, когда все целевые гексы голографического контура соответствуют требуемым высотам в конфигурации фигуры, при условии, что все 3 мини-монумента были предварительно активированы.

---

### ЭТАП 6: Модернизация Интерфейса (`/components/GameHUD.tsx` и `GameView.tsx`)

Создаем атмосферные элементы управления для тактической обороны и поиска схем.

1. **Панель Осады (Defense HUD):**
   * Полоса прочности Ядра («Core Integrity») с предупреждающим миганием при уровне здоровья $< 30\%$.
   * Счетчик волн врагов («WAVE 1 / 3») и оставшихся ботов на карте.
   * Таймер до прибытия подкрепления / окончания осады.
2. **Панель Головоломки (Puzzle HUD):**
   * Статус-бар мини-монументов: `[ ✦ ] [ ✦ ] [ ✧ ]` (Активировано 2/3).
   * Датчик приближения к скрытому монументу (пищащий радар, ускоряющий мигание при приближении в тумане войны).
3. **Размещение Защитных Сооружений (Turrets):**
   * Кнопка быстрой установки накопленных защитных турелей на возвышенности ($L2+$). Чем выше установлена турель, тем больше её радиус атаки (бонус за высоту!).

## 3. ПОСЛЕДОВАТЕЛЬНОСТЬ РАЗРАБОТКИ И ТЕСТИРОВАНИЯ

Для постепенной интеграции без поломки существующей логики рекомендуется следующий порядок внедрения:

```
+-----------------------------------------------------------------+
|                                                                 |
|  Шаг 1: Обновление метаданных, типов и моделей в types.ts      |
|  Шаг 2: Внедрение механики 3-х Мини-Монументов на уровнях        |
|  Шаг 3: Разработка ИИ штурмовых ботов для осады Ядра            |
|  Шаг 4: Развертывание Конструктора Форпоста (Core Base Builder) |
|  Шаг 5: Стыковка систем и балансировка (Victory/Defeat)         |
|                                                                 |
+-----------------------------------------------------------------+
```

Эта архитектурная модернизация решает основную проблему мотивации игрока: теперь каждый сыгранный уровень, каждая собранная фигура и каждый добытый блок имеют значение, защищая сердце вашей симуляции — Энергетическое Ядро.
